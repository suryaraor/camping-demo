Features

Everything a group trip needs

Six coordinated views, one shared data source.

📅

Trip Schedule

Day-by-day meal and activity planner with volunteer assignments and status tracking.

  • Grouped by day and meal type (Breakfast / Lunch / Dinner / Activity)
  • Meal icons and color coding per type

Shared grocery tracker grouped by store and volunteer, with a real-time progress bar.

Family Signups

One-click registration with headcount, nights attending, and dietary notes.

Volunteers

Roster of volunteers with store assignments and contact info.

  • Family affiliation tracking
  • Assigned task completion monitoring
  • Phone contact for coordination

Offline-First

Works at the campsite even without cell signal — syncs when connectivity returns.

  • Auto-sync on reconnect
Architecture

Under the hood

Three layers. No servers. No bills. Here's how data flows from your browser to Google Sheets and back.

🙋 User
Browser Mobile

Opens the app on any device — phone at the campsite, laptop at home. No app store. No install. Just a URL.

⇄
⚛️ Frontend
React 18 Babel CSS Variables localStorage

Single HTML file. React and Babel load from CDN — no npm, no webpack, no build step. All state, caching, and offline logic lives here.

Offline queue active when no signal
⇄
⚙️ Apps Script
Google Apps Script REST API CORS

~250 lines of JavaScript deployed as a Google Web App. Handles all reads and writes. Google runs it for free on their infrastructure — 0 servers to manage.

⇄
📊 Google Sheets
6 Sheet Tabs Auto Headers Row IDs

Acts as the database. Each tab is a table: Schedule, ShoppingList, Volunteers, Families, Expenses, Signups. Non-technical teammates can open the sheet and see/edit the data directly.

Request lifecycle — marking a shopping item purchased
1
User taps "Purchased"
UI updates immediately (optimistic) — no waiting.
2
POST to Apps Script
fetch() sends action=updateStatus&id=…&status=Purchased to the /exec URL.
3
Sheet updated
Apps Script finds the row by ID, writes "Purchased" to the Status column.
4
Response returns
Success JSON confirms the write; cache is invalidated for the next read.
5
Offline? Queued
If no signal, write goes into localStorage pending queue and replays on reconnect.

Why this works at scale

☁️
Google runs your backend
Apps Script runs on Google's infrastructure — the same fleet that serves Gmail and Sheets. You get auto-scaling, uptime, and global edge presence for free within Google's generous quotas (20,000 requests/day).
📊
Google Sheets is a capable database for small apps
For groups under ~500 rows per sheet, Sheets performs like a real database. It handles concurrent edits, revision history, and can be read by non-technical admins without any SQL knowledge.
🚀
GitHub Pages is a CDN
Your single HTML file gets served from GitHub's global edge network. HTTPS included. Custom domain supported. No Nginx, no SSL certs, no config — just push to the gh-pages branch.
🧠
No build = zero DevOps overhead
No CI/CD to maintain, no npm audit vulnerabilities to patch, no container to update. Deployment is literally opening the file in your editor and saving it to GitHub.
Build Your Own

Deploy your version in ~10 minutes

Here's exactly how the system was built and how to replicate it for any group coordination use case.

1

Create the Google Sheet

Go to sheets.google.com and create a new spreadsheet. Note the spreadsheet ID from the URL — it's the long string between /d/ and /edit.

# Your Sheet URL looks like: https://docs.google.com/spreadsheets/d/YOUR_SPREADSHEET_ID/edit # Create 6 tabs named: Schedule | ShoppingList | Volunteers | Families | Expenses | Signups
💡 The Apps Script's setupSheetHeaders() function can create all tabs and headers automatically for you — just run it once after deploying.
2

Deploy the Google Apps Script backend

In your Sheet: Extensions → Apps Script. Paste in Code.gs, set your spreadsheet ID, then deploy as a Web App.

// Top of Code.gs — set your sheet ID const SPREADSHEET_ID = 'your-sheet-id-here'; // Key pattern: every action routes through doGet / doPost function doGet(e) { const action = e.parameter.action; if (action === 'getSchedule') return corsResponse(getSchedule()); if (action === 'getShopping') return corsResponse(getShopping()); // ... more actions } // Deploy: Execute as "Me" → Access "Anyone" → Deploy // Copy the /exec URL — this is your API endpoint
🔑 The Web App /exec URL acts as your API key. Only share it with people who need write access.
3

Configure the frontend

Open index.html, find the config constants near the top of the script, and paste in your Apps Script URL.

// index.html — two constants to set const APPS_SCRIPT_URL = 'https://script.google.com/macros/s/YOUR_ID/exec'; const USE_MOCK_DATA = false; // true = demo mode, no real backend // That's it. The whole app is self-contained in this one file.
🧪 Keep USE_MOCK_DATA = true while designing — the app ships with realistic sample data for all 6 views.
4

Deploy to GitHub Pages

Push index.html to your repo's gh-pages branch. GitHub automatically serves it at your Pages URL. Done.

git checkout -b gh-pages git add index.html git commit -m "deploy camping app" git push origin gh-pages # Live at: https://<your-username>.github.io/<repo-name>/ # Free HTTPS included. No config needed.
🌐 Alternatively: drag index.html onto Netlify's dashboard — it deploys in seconds with a random URL you can share immediately.
5

Share the URL with your group

Send the GitHub Pages URL to everyone. No login required. The app handles all coordination from here — shopping, expenses, schedule, volunteers.

# Share this link with your group: https://your-username.github.io/camping-planner/ # Admins can also view / edit data directly in Google Sheets # Real-time collaboration built in — no extra setup
The Bigger Picture

Why this pattern is powerful

This isn't just a camping app. It's a reusable pattern for building real collaborative tools with zero infrastructure.

⚡

Idea to live app in an afternoon

No boilerplate, no environment setup, no deployment pipeline. Open a text editor, write some React, paste a URL, push to GitHub. You're live.

🔧

The database is a spreadsheet

Non-technical teammates can read, edit, and export the data in Google Sheets. No SQL, no database client, no access controls to configure. Sheets is the admin panel.

📱

Offline-first out of the box

The localStorage cache + pending write queue pattern makes the app resilient to bad connectivity. Users see data immediately and writes are queued automatically.

🧩

Adapt it to any group coordination need

The sheet-as-database pattern, offline caching, and Apps Script API layer are reusable scaffolding. Swap the domain — same architecture.

🔒

Secure enough for small trusted groups

The Web App URL is your API key. Google's OAuth controls who can view the underlying sheet. For a private group of 10–50 people, this is genuinely appropriate security.

📈

Scales further than you'd expect

Apps Script allows 20,000 requests/day on the free tier. Google Sheets handles thousands of rows without issue. This can serve a group of hundreds with no cost increase.
